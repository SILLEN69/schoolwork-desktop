# Lesson Studio — 0.9.0 implementation and verification plan

1. **Immediate model selection:** capture the selected value synchronously, display it immediately, serialise persistence, protect it from stale settings refreshes, and restore the last confirmed value with a visible error if saving fails. Existing running tasks keep their own model.
2. **Whisper:** Swedish `kb-whisper-large` by default; English `faster-whisper-large-v3` via language buttons. Audio uploads and microphone recording use the existing encrypted TeachGPT key in the main process. Complete 16 kHz mono PCM WAV segments are captured about every 20 seconds. The expected OpenAI-compatible endpoint is `POST https://teachgpt.ssis.nu/api/v1/audio/transcriptions` with multipart `file`, `model`, `language` and `response_format=json`. This route still needs live school-service confirmation. The TeachGPT screenshot confirms upload/microphone/live support, not its HTTP contract. No alternate provider is used automatically.
3. **Dedicated UI:** Swedish-first Lesson Studio and ordinary Transcription views. Transcript left, structured overview/concepts centre, class tasks and future assignments right. Pause/continue, audio import, automatic/manual summary, Markdown export, saved session history and session deletion. Recording language changes are disabled until capture and upload finish.
4. **Durability:** transcript and validated summaries stay in the existing app profile database. Failed audio remains under `lesson-audio/<session>/<segment>` for retry; successful audio is deleted. Segment IDs prevent duplicate transcript entries. Queue backpressure pauses recording. Raw audio is sent to the school service; summaries use the chosen chat model. Evidence excerpts must occur verbatim in the transcript. Summary date suggestions are shown for review, never silently written to Calendar.
5. **Connected Google Calendar:** OAuth Desktop app client, loopback callback bound to 127.0.0.1, random state, PKCE, encrypted client secret/refresh token, narrowly scoped calendar.events permission, reconnect/disconnect, and a reviewed title/date before creating an all-day assignment event. Deterministic event IDs allow retries after ambiguous network failures without duplicate events. A Google Cloud project with Calendar API enabled and a Desktop OAuth client is required. Enter its client settings in the in-app Calendar connection screen, never in chat. Testing-mode clients may need test users and can have short-lived refresh tokens. A distributed production client requires the app owner to provide and configure it.
6. **Verification/release:** unit tests for audio payloads, retry/deduplication, persistence, malformed/unsupported summary output, dates, OAuth state/PKCE/token refresh and calendar conflicts. UI smoke tests for recording/import, Swedish/English, lesson layout, task completion, calendar review, session restore and model selection while saves/settings refreshes are delayed. Build TypeScript/frontend/backend; cross-compile the Windows .NET helper; package Windows x64 installer and portable; verify manifest checksums and included helper. Windows native desktop automation and live microphone/TeachGPT/Google-account calls require a final check on the laptop. Do not label simulated provider or Linux checks as live Windows checks.

This is a coding task: tracked application files are intentionally changed. No personal profile or real credentials are included in test data or packages. Packaging does not publish a GitHub release.
