# SchoolWork 0.7: bounded progress, ordered chat and actual phone replies

## Evidence

Read-only inspection of the installed app's SQLite task/events/tool/diagnostic records and its visible window identified a draft-and-memory task with 47 provider requests over approximately 525 seconds. Provider waits accounted for about 505 seconds; tools accounted for about 20 seconds. Saving the managed note itself took under 0.1 second. These totals are not a future speed guarantee.

The task snapshot had screen input disabled, so native mouse/keyboard schemas were filtered out. The prompt nevertheless implied that those tools existed. The agent substituted PowerShell window/keyboard automation. Repeated capture failures alternated with unrelated successful reads. Workspace Markdown writes falsely armed the code-verification gate. The agent rediscovered the memory vault, copied its note format and tried to edit an automatically generated index, producing a stale-hash failure. The renderer displayed all messages first and all tool activity afterwards. None of this is evidence that mail was sent.

No credentials, personal email content, task identifiers or database copies are committed here. The user's existing app, mail drafts and saved conversations were not used as destructive test fixtures.

## Implementation and trade-offs

1. `ProgressGuard` preserves repeated failures across unrelated successful reads: warning at two failures, checkpoint at three for the same tool/target/failure class.
2. Desktop observation streaks warn at six and stop at twelve; four identical frame hashes without a successful action stop an unchanged-screen loop. Hashes contain no pixels. A successful action resets the streak. This is bounded recovery, not proof of task completion.
3. Each request states actual input availability. All desktop schemas remain known; validated execution still checks capabilities, foreground identity, fresh one-use observations, cancellation and bounds.
4. Full desktop access is the requested default. A one-time 0.7 policy migration enables the launch/view/input/all-app flags and unfinished task snapshots. Subsequent user revocations remain sticky across restarts. The AI can release input only for its own task; it cannot use that tool to re-enable input or override Stop.
5. Source/project edits still require a successful check after the last edit. Markdown notes, ordinary documents and mail drafts no longer trigger the coding gate or a coding-success catchphrase. Opening a compose URL is not evidence of Gmail autosave or sending.
6. `memory_save` persists a requested fact, reads it back and validates its search-index body in one call. Exact title/body matches are deduplicated using a bounded metadata lookup rather than reading every note. Saved facts remain provisional: persistence is verified, not factual truth. The generated index remains managed by the vault.
7. The central chat merges saved messages and grouped tool activity. New activity carries an explicit message-sequence anchor; older records use timestamps without rewriting the database. The final reply follows its preceding tools. Coalesced event refreshes, focus recovery and active-task reconciliation restore missed updates.
8. Sidebar refreshes request only conversation metadata instead of repeatedly loading every conversation's full tool/message history. Event anchors use an indexed maximum-sequence lookup. Native tool batches stay contiguous before recovery hints and screenshot messages.
9. Windows captures use visible DWM frame bounds consistently for capture and input validation. `GetWindowRect` includes invisible resize borders; [Microsoft documents the distinction](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect). Observation no longer requires foreground focus; unfocused frames are marked potentially occluded and issue no input token. Input remains focus-checked. Truly off-screen/minimized/protected windows remain explicit failures.
10. Telegram accepts text with “gotcha, I’m on it” and images with a short picture acknowledgement. Actual task-specific final replies are delivered from desktop and phone tasks; action results are prompted to be brief and questions as detailed as needed. No visible task/model boilerplate is added. Buttons and reply routing retain the exact task identity. Failure checkpoints are short; detailed evidence stays in Activity and explicit status answers.

No separate notification-rewriting inference is required: the existing agent produces its fresh final using tool evidence. Model compliance and reasoning quality still depend on TeachGPT. A useful task may need more than one capture; limits deliberately prefer an honest checkpoint over indefinite retries. Explicit retry begins from saved evidence, not blind input replay.

## Privacy and cancellation

Paired phone delivery now includes requested desktop results, potentially private content. Settings discloses this. Token storage, private chat/sender authentication, session separation, Unicode-safe chunking, deduplication and the durable outbox remain in place. No screenshots are automatically sent to Telegram. Bot chats are not Secret Chats. Known-secret redaction is not comprehensive data-loss prevention.

Stop disables native input, invalidates observations, aborts active tasks and stops task-owned processes; ordinary user applications are not killed. The agent's release tool does not stop other tasks or persist a global disable. Normal Windows/UAC/locked-desktop/elevated-window limitations remain. PowerShell/process access remains normal-user, unsandboxed execution. Common GUI-input workarounds are rejected when input is off, but pattern recognition is not a security sandbox around arbitrary shell code.

## Verification and acceptance

- 116 unit tests cover verification scope, interleaved failure streaks, observation/frame budgets, image-coordinate mapping, unfocused observation without input tokens, capability revocation, one-call memory persistence/index/deduplication (including externally edited facts) and same-millisecond/legacy timeline ordering.
- Isolated real Electron integration completes a synthetic local draft + memory save in three mocked provider requests, without a code gate; commentary/tool/final order survives reload. Three failed captures with successful intervening searches still end in a checkpoint. Agent release leaves the schema registered but changes execution status.
- Native and JSON-fallback desktop workflows have completed capture, mouse click, Unicode/multiline typing, shortcuts, scroll and UI Automation inspection in a disposable WinForms fixture. Two physical monitors were enumerated and window movement/capture checked. Password controls and persisted screenshot pixels remain excluded.
- The fixture's classic multiline TextBox did not handle Ctrl+A, allowing old text to remain while a weak substring assertion passed. Microsoft documents [the older multiline Ctrl+A issue](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.textbox.processcmdkey?view=windowsdesktop-10.0). The test app now implements its own Select All shortcut, and both tool protocols must produce exactly the expected replacement text. Mock window selection also matches the disposable executable explicitly, never the first unrelated foreground app. This does not prove that every third-party app implements the same shortcut.
- Telegram transport/provider tests are mocked. They verify actual desktop outcome delivery, long question delivery, incoming messages/photo/document images, persistence, reply routing, busy rejection, foreign-sender rejection, retries, Stop and duplicate prevention. They do not prove live Telegram delivery or model vision quality.
- Packaged 0.7.0 isolated-profile restart passed: user Stop remained disabled until an explicit user enable, saved SQLite/images and bundled math assets restored, and the bundled Windows helper captured the disposable window. Installer and portable build succeeded. The installer is unsigned. The running user's installed app was not updated or stopped.
- Remaining manual checks: live TeachGPT reasoning and vision, live paired phone delivery, Gmail autosave, maximized third-party windows, mixed 125/150% monitor DPI, interrupted network delivery and elevated/UAC/lock cases. Mail must not be sent to test a draft-only request.
