# Workflow design and verification — 0.10

## Evidence and decisions

The current Electron/React app already has a durable SQLite conversation/tool journal, Windows desktop helper, TeachGPT streaming, local lesson metadata/audio storage, and Calendar loopback PKCE OAuth. Extend those boundaries rather than adding a second agent or changing providers.

A read-only inspection of seven current-day tasks found two stopped at verification/plan bookkeeping, four completed and one deliberately cancelled. Passing custom Node check scripts were not recognized. One reasoning-only provider recovery completed without usable content; another attempt hit its progress deadline. Repeated exact-patch failures and desktop focus failures were also recorded. Cancellation remains cancellation, not an automatic retry. Private chat contents, credentials and database files are not included in this repository.

The lesson example contained a specific reading assignment and a vague recap for the same date. Model IDs were unstable; numeric page ranges and evidence must be compared before transferring persisted completion/calendar identity. Application-side deduplication complements the model prompt; ambiguous distinct deliverables stay separate. Already-linked events are preserved even if a later summary omits them.

## Boundaries

1. **Steering:** renderer sends chat:steer with conversation, active task and idempotency ID. Main validates ownership, atomically appends the user message/attachments and queues input. Active tool calls finish normally. New instructions are added at the next model/tool boundary. A model response generated before new guidance is discarded before dispatching its action. This is safe-step steering, not native provider mid-token steering. Stop remains explicit. Queue state survives restart; interrupted tasks pause rather than automatically replay effects.
2. **Voice:** Work dictation uses the same audio service as lessons, but inserts text into the existing composer. Successful temporary sessions are cleaned up after insertion; failed audio is retained for retry, keyed to the conversation. Audio chunks keep the microphone open during uploads, cut at silence when possible and overlap two seconds. Backpressure pauses capture instead of growing an unbounded queue. Re-entrant stop cannot emit the same chunk twice. Original transcript segments remain available; AI tidying is optional, revision-checked and rejects oversized input instead of silently truncating it.
3. **Lessons:** a single readable content pane replaces three independently scrolling columns. Subject inference is based on lesson content/model hints, not transcription language. Users can override subject. Questions use normal Work tasks with bounded, untrusted lesson context; recording can continue while the agent responds.
4. **Google:** tokens stay in main, encrypted using Electron safeStorage. Calendar writes use deterministic valid IDs and recover 409 conflicts by reading that event. Native read tools avoid screen automation where an API exists. Drive is optional read-only; Google Docs/text only, bounded output, cancellation and one token-refresh recovery. OAuth setup and school permission are not inferred from a screenshot.
5. **MCP:** user-configured Streamable HTTP endpoints only; HTTPS or loopback HTTP, no credentials/query secrets in URLs, no redirect following. Discover schemas on demand instead of adding every tool to each model request. Validate arguments before calling; schema, response and context sizes are bounded. No automatic action retries, including the SDK's header-mismatch retry path. Public/bearer auth only; interactive auth requests are reported, not guessed. Disabling/removing a connection aborts its active requests. Remote tool data/descriptions are untrusted, not new permissions.
6. **Completion:** recognize actual named custom test/check/verify scripts and assertion-bearing inline Node tests, not echoed claims. A successful command only verifies what it checked. Repeated successful checks are blocked after warnings, reset by a new edit. An unfinished plan gets one reconciliation reminder; bookkeeping alone cannot suppress every user-facing answer. Actual unchecked code still checkpoints with an honest limitation. Failure context is bounded rather than reloading large repeated memory excerpts.

## Tests and acceptance

- Unit tests: task identity/deduplication, page-range separation, subject inference, transcript overlap/refinement invalidation, complete WAV chunks/re-entrant stop, durable/idempotent steering and rollback, custom Node verification, passing-check loop bounds, valid Calendar IDs/error classification, real MCP client with a loopback JSON-RPC server and invalid-argument rejection.
- Real Electron integration: synthetic microphone -> multipart transcription -> saved continuous text; model selection races/failures; structured notes, completion, Calendar OAuth callback and duplicate writes; failed-audio retry; English/Swedish switching; lesson question with context; Work dictation edits the composer without sending; follow-up during a real Node tool run finishes that tool and reaches a final answer; application restart retains lesson/tasks. Remote TeachGPT/Google responses are simulated, not claimed as account-level verification.
- Windows desktop fixture: actual helper -> parent window -> modal file picker -> focused filename -> selected file; stale observation reuse rejected. Personal email/browser windows are not test targets.
- Release: build/unit/UI checks before packaging, helper source/binary hashes verified, installer/portable/manifest/blockmap checksums verified before publishing. Check public release/feed and simulate an older app discovering/downloading the published installer without installing it.
- Manual account acceptance still required: import an allowed Desktop client, enable Calendar/Drive API, log in, run read check, save one reviewed assignment, refresh summary without another event, reconnect revoked access and inspect actionable errors. Test real Swedish speech at chunk boundaries and on noisy microphones. Test supported MCP servers under their own accounts/scopes.

## Rollout and limits

SQLite changes are additive and originals are preserved. No personal profile is rewritten by tests. Successful audio is removed; failed audio remains until retry/discard/session deletion. Lesson deletion does not delete Google events. Transcripts/attached images are sent to TeachGPT when used; connected APIs receive only their request data, but tool results may subsequently enter model context. Connection secrets are never returned to the renderer.

Full-user file/shell/desktop access is powerful, not a security sandbox. UAC secure desktop/elevated apps cannot be controlled by a normal helper. A timed-out external write may have succeeded: inspect its state rather than blindly trying again. AI refinement/deduplication can be wrong; originals, evidence and manual edits are available. Subject inference is conservative and overrideable. Long transcripts retain originals and can exceed the single-request tidying limit.

Before wider school/municipal distribution: sign installer/update binaries, independently audit IPC/tool/OAuth boundaries, complete privacy/data-processing and recording policies, provide retention/export/account-removal controls and an administrator-approved OAuth app, perform accessibility and real multi-monitor/focus testing, and remediate dependency advisories. Passing fixture tests is not enterprise readiness or equal model intelligence to a frontier AI company.

Dependency audit after the patch: production dependency audit reports zero known advisories. Full audit still reports eight moderate build-tool advisories in the Electron packaging download/logger chain; no critical/high findings remain. These are not bundled runtime dependencies and are not represented as fixed. Use locked, reviewed CI inputs and remediate the packaging chain before institutional rollout.

## Official architectural references

- [Codex app-server steering vs interrupt](https://learn.chatgpt.com/docs/app-server): separate steering from cancellation and retain durable streamed task events. SchoolWork implements the pattern locally for TeachGPT, not the Codex service.
- [Google Calendar errors](https://developers.google.com/workspace/calendar/api/guides/errors), [event insertion and ID alphabet](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert), [installed-app OAuth](https://developers.google.com/identity/protocols/oauth2/native-app).
- [MCP TypeScript client](https://ts.sdk.modelcontextprotocol.io/v2/clients/connect.html): direct HTTP tool connections with explicit auth/cancellation boundaries.
- [Vitest migration](https://vitest.dev/guide/migration/): patched test tooling on supported Node/Vite versions; runtime and build-tool advisories are reported separately.
